# Codex 首字慢自动切换

管理员入口：系统设置 → 网关 → 网关转发 → Codex 首字慢自动切换。

| 设置 | 默认值 | 范围 |
| --- | --- | --- |
| `openai_ws_latency_switch_enabled` | `false` | 开启 / 关闭 |
| `openai_ws_latency_switch_consecutive` | `3` | 1–20 次 |
| `openai_ws_latency_switch_slow_ms` | `15000` | 1000–300000 毫秒 |
| `openai_ws_latency_switch_probe_count` | `6` | 2–20 个候选账号（不含当前账号） |
| `openai_ws_latency_switch_wait_seconds` | `300` | 1–3600 秒 |

功能监控 OpenAI Responses WebSocket 和 HTTP SSE 请求。WebSocket 按线程计数，HTTP SSE 按稳定会话标识计数；均按分组、API Key 和模型隔离。工具结果续轮、预热和后台辅助请求不计入用户提问次数。正常请求或失败请求打断连续慢计数，首字时间沿用后台配置的 semantic / visible 口径。

达到连续次数后，后台并发探测配置数量的候选账号，不再探测当前账号作为速度基准。并发数范围为 2–20，默认 6；保存后从下一批探测生效，无需重启。每批最多执行 5 轮，每轮重新随机选择候选账号探测。任一候选首字时间低于 5 秒时立即选中并取消同轮其他探测；否则等待本轮完成，在首字时间低于 10 秒的账号中选择最快者。没有符合条件的账号时开始下一轮。探测使用合成短提示，不发送用户历史，消耗上游额度，不计入用户账单。候选仍受分组、模型、隐私、利润、协议、配额及并发条件限制。每个服务实例的探测总并发同样受配置路数限制；实际路数可能因可用账号数量或并发不足而减少。降低路数不会中断已经开始的探测，后续轮次使用新上限。没有可用候选或五轮均未达到 10 秒时保持原路由。

候选首字时间严格低于 10 秒即可成为待切换目标，不再与当前账号比较。首字时间低于 5 秒的候选可立即选中；其余情况下，选择本轮低于 10 秒且速度最快的候选。每次探测后冷却五分钟；待切换目标有效期由「等待用户下次连接时间」设置控制，默认五分钟。状态通过 Redis CAS 保存，可跨服务实例重连。

发现符合条件的候选后，等下一次用户提问到达，在写入旧上游之前要求客户端重试：WebSocket 返回自定义关闭码 `4001`，HTTP SSE 返回 `529` 且错误码为 `sub2api_latency`；HTTP/1 同时关闭连接。错误消息使用通用文本，不说明主动断开的原因。工具结果回传继续完成。重连优先选择探测目标，并在目标繁忙时允许其他符合条件的账号接管，恢复期间排除原账号。目标必须重新通过正常调度和并发检查。

恢复要求：客户端移除旧 `previous_response_id`，发送本地保留的完整有效上下文，包括压缩结果及配对的工具调用记录。服务端在原始客户端请求进入现有续链修复之前检查这个条件。WebSocket 仍携带旧引用或缺少工具调用上下文时返回 1008；HTTP 重试仍携带旧引用或缺少完整输入时返回 400，避免重复重试和丢失上下文。预热响应不视为已完成上下文恢复。只有新上游成功处理用户请求后，才完成本次切换。

## 验证

服务端自动化测试覆盖连续计数、正常请求清零、工具回传、作用域隔离、过期、关闭开关、Redis 跨实例 CAS、真实 WebSocket 关闭路径，以及 HTTP SSE 重试门控和目标账号选择。它们不能证明特定 Codex 版本的自动重试行为。

在测试环境用实际 Codex 客户端执行：第一轮发送唯一测试暗号且只要求回复“收到”；待记录出现 `openai.ws_latency_switch_pending` 后，下一轮询问暗号。分别测试 WebSocket 关闭码 4001 和 HTTP SSE 529（错误码 `sub2api_latency`）后，确认客户端是否自动重试；检查客户端重试请求是否移除了旧引用、保留有效历史，再确认由新账号回答。分别验证普通多轮、发生过工具调用的对话、压缩后的对话。应同时检查原始入站帧和出站请求，避免把网关自身的续链修复误判为客户端自动恢复。

日志事件：`openai.ws_latency_probe_started`、`openai.ws_latency_probe_completed`、`openai.ws_latency_switch_pending`、`openai.ws_latency_reconnect_requested`、`openai.ws_latency_http_retry_requested`、`openai.ws_latency_reconnect_received`、`openai.ws_latency_recovery_context_required`、`openai.ws_latency_switch_completed`。日志会记录传输类型、原始输入条数、是否携带响应引用及工具上下文是否配对。这些事件不记录用户对话内容或密钥。

管理员「首字慢切换记录」中的探测完成、待切换、请求重连和切换完成事件会记录触发用户的 ID、用户名、邮箱及 API Key ID，列表中的「触发用户」列显示用户名、邮箱和用户 ID。用户信息取自请求鉴权结果，不记录 API Key 密钥。更新前未记录用户信息的历史事件显示为 `-`，无法补回。

默认保持关闭，按所使用客户端版本的端到端验证结果决定是否启用。
