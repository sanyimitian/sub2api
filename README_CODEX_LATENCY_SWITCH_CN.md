# Codex 首字慢自动切换

管理员入口：系统设置 → 网关 → 网关转发 → Codex 首字慢自动切换。

| 设置 | 默认值 | 范围 |
| --- | --- | --- |
| `openai_ws_latency_switch_enabled` | `false` | 开启 / 关闭 |
| `openai_ws_latency_switch_consecutive` | `3` | 1–20 次 |
| `openai_ws_latency_switch_slow_ms` | `15000` | 1000–300000 毫秒 |
| `openai_ws_latency_switch_probe_count` | `6` | 2–20 路（含当前路由） |

功能针对有明确线程或会话身份的 OpenAI Responses WebSocket 连接。按分组、API Key、线程和模型隔离计数；工具结果续轮、预热和后台辅助请求不计入用户提问次数。正常请求或失败请求打断连续慢计数，首字时间沿用后台配置的 semantic / visible 口径。

达到连续次数后，后台按配置的探测路数执行探测，包含当前账号作为对比基准，其余为候选账号。例如配置为 4 路时，探测当前账号及最多三个候选账号。最少 2 路用于对比，默认 6 路，最多 20 路；保存后从下一批探测生效，无需重启。等待本批探测结束后选择更快的路由。探测使用合成短提示，不发送用户历史，消耗上游额度，不计入用户账单。候选仍受分组、模型、隐私、利润、协议、配额及并发条件限制。每个服务实例的探测总并发同样受配置路数限制；实际路数可能因可用账号数量或并发不足而减少。降低路数不会中断已经开始的探测，后续批次使用新上限。没有当前路由基准、没有候选或提升不明显时保持原路由。

候选需比当前探测基准至少快 20%，且快超过 250 毫秒。每次探测后冷却五分钟，待切换目标有效两分钟。状态通过 Redis CAS 保存，可跨服务实例重连。

发现更快路由后，等下一次用户提问到达，在写入旧上游之前返回 WebSocket 1013 关闭帧。工具结果回传继续完成。重连优先选择探测目标，并在目标繁忙时允许其他符合条件的账号接管，恢复期间排除原账号。目标必须重新通过正常调度和并发检查。

恢复要求：客户端移除旧 `previous_response_id`，发送本地保留的完整有效上下文，包括压缩结果及配对的工具调用记录。服务端在原始客户端帧进入现有续链修复之前检查这个条件。仍携带旧引用或缺少工具调用上下文时返回 1008，避免重复 1013 和丢失上下文。预热响应不视为已完成上下文恢复。只有新上游成功处理用户请求后，才完成本次切换。

## 验证

服务端自动化测试覆盖连续计数、正常请求清零、工具回传、作用域隔离、过期、关闭开关、Redis 跨实例 CAS，以及真实 WebSocket 在请求到达旧上游前关闭的路径。它们不能证明特定 Codex 版本的自动重试行为。

在测试环境用实际 Codex 客户端执行：第一轮发送唯一测试暗号且只要求回复“收到”；待记录出现 `openai.ws_latency_switch_pending` 后，下一轮询问暗号。检查 1013 后是否无需人工操作就重连，检查客户端原始帧是否移除了旧引用、保留有效历史，再确认由新账号回答。分别验证普通多轮、发生过工具调用的对话、压缩后的对话。应同时检查原始入站帧和出站请求，避免把网关自身的续链修复误判为客户端自动恢复。

日志事件：`openai.ws_latency_probe_started`、`openai.ws_latency_probe_completed`、`openai.ws_latency_switch_pending`、`openai.ws_latency_reconnect_requested`、`openai.ws_latency_reconnect_received`、`openai.ws_latency_recovery_context_required`、`openai.ws_latency_switch_completed`。重连日志记录原始输入条数、是否携带响应引用及工具上下文是否配对。这些事件不记录用户对话内容或密钥。

默认保持关闭，按所使用客户端版本的端到端验证结果决定是否启用。
