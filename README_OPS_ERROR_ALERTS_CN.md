# 上游错误条数告警（邮件 / QQ群）

在「运维监控 → 告警规则」点击「添加 502/503 告警」，可快速创建规则：

- 默认统计最近 5 分钟的上游 502、503 错误，合计超过 20 条时触发，即至少 21 条。
- 阈值、状态码、统计窗口、平台、分组、持续时间、冷却时间均可修改。窗口支持 1～1440 分钟。
- 「持续时间」为 0 时，首次检查满足条件就触发；大于 0 时需连续满足条件。
- 「排除模型」支持从使用记录中搜索，也支持手动输入多个名称。按用户请求的模型名精确匹配，区分大小写；模型映射不会改变排除结果。旧记录没有请求模型名时使用原始 model 字段。
- 统计采用运维上游错误列表口径：优先使用上游状态码，包含同步、流式和列表中可见的已通过重试恢复的上游错误；每条日志计一次，不展开内部重试明细，不计入业务限制类错误。排除模型不计入总数和状态码汇总。

例如，5 分钟内有 30 条错误，其中排除模型产生 12 条，实际计数为 18，不触发默认告警。

## 通知设置

邮件：在系统设置中配置 SMTP，在运维设置中启用预警邮件并添加收件邮箱，在规则中勾选「发送邮件通知」。可以使用系统设置中的邮件测试功能验证 SMTP。

QQ群：在「运维设置 → QQ群机器人通知」选择机器人类型，支持 OneBot v11 和 QQ 开放平台官方机器人。已有配置默认使用 OneBot，无需重新填写。

### OneBot v11（如 NapCat）

1. 填写机器人 HTTP 接口的**基础地址**，如 `http://127.0.0.1:3000`，系统会调用 `/send_group_msg`。
2. 填写目标群号和访问令牌，开启 QQ 通知并单独保存。令牌不回显；编辑时留空保留，勾选清除可删除。
3. 点击「保存并发送测试通知」验证连接，然后在告警规则中勾选「发送QQ群通知」。

基础地址必须能从 Sub2API 后端访问。容器内的 `127.0.0.1` 指向容器自身，机器人在另一容器时应使用对应服务地址。机器人需保持在线并具有目标群的发送权限。

### QQ 开放平台官方机器人

1. 在 [QQ 开放平台](https://q.qq.com/)创建支持群聊的机器人，获取 **AppID** 和 **AppSecret**，将机器人加入目标群；按平台要求配置 Sub2API 服务器的出口 IP 白名单。
2. 机器人类型选择「QQ 开放平台官方机器人」，**暂时关闭 QQ 通知**，填写 AppID、AppSecret 后点击「单独保存 QQ 配置」，目标群 OpenID 可留空。AppSecret 不回显，留空保留原值。
3. 在 QQ 开放平台的「事件订阅 / Webhook」中，填写卡片显示的回调地址：`https://你的域名/api/v1/ops/qq-bot/webhook`。使用公网可访问的 HTTPS 地址，反向代理需放行此 POST 路径；不要要求登录、验证码或添加浏览器挑战。服务器自动完成 QQ 的地址验证。
4. 订阅 `GROUP_AT_MESSAGE_CREATE`（群内 @ 机器人）、`GROUP_ADD_ROBOT`（入群）、`GROUP_DEL_ROBOT`（退群）。在目标群中 @ 机器人并发送文字，然后回到卡片点击「刷新回调状态与群列表」。点击「使用此群」填入 **group_openid**，它不是普通 QQ 群号。
5. 开启 QQ 通知，点击「保存并发送测试通知」，再在告警规则中勾选「发送QQ群通知」。目标群需允许机器人主动发送消息。

回调公开接口不需要管理员登录，但事件必须通过 AppID 和 Ed25519 签名验证。仅保存最近 50 个群的 OpenID、事件类型和收到时间，不保存消息内容，也不自动回复聊天。切换 AppID 或 AppSecret 后，发现列表按新凭据隔离，需要重新触发群事件。群发现和回调接收在通知开关关闭时也可使用，选择群不会自动改变告警目标，需管理员明确保存。

回调验证失败时，先确认凭据已保存，回调地址返回的是 API 响应而不是登录页；未保存凭据时返回 503，AppID 或事件签名不匹配时返回 401。只在浏览器打开回调地址不能验证是否成功，应使用 QQ 平台的验证操作。群事件没有出现时，检查订阅范围和机器人沙箱/正式环境的可用群配置。

系统使用正式环境 `https://api.bot.qq.com`，自动获取并缓存 Access Token，在临近到期时刷新；鉴权返回 HTTP 401 时重新获取令牌并重试一次。切换机器人 AppID 或 AppSecret 后不会复用旧凭据的缓存。无需填写 OneBot 地址或手工维护 Access Token。

告警使用纯文本主动消息。按当前[官方消息规则](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/overview.html)，群主动消息每群每分钟最多 20 条、每日最多 1000 条，另受机器人整体频控限制，实际以平台最新规则为准。关闭主动消息接收、机器人未入群/被禁言、权限不足或达到频控时会发送失败；可在告警详情查看错误码和排查提示。告警文本包含链接时还受平台 URL 规则限制。

若测试返回 `40034105`（主动消息失败、无权限），说明 QQ 拒绝了当前机器人对该群的主动消息。请检查群内机器人“允许主动发送”设置及开放平台消息权限；回调验证成功、收到群事件或拿到 `group_openid` 不代表已获得主动发送权限。若平台未向该机器人开放此能力，无法通过修改回调地址解决自动告警发送，应改用 OneBot 或邮件。页面会保留具体错误提示，保存成功但测试失败不会显示测试成功。

接口参考：[鉴权与令牌](https://bot.q.qq.com/wiki/develop/api-v2/dev-prepare/interface-framework/api-use.html)、[发送群聊消息](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_groups_group_openid_messages.post.html)。

邮件和 QQ 可以分别开启，也可以同时开启。QQ 配置在自己的卡片中单独保存。

## 检查与防重复

在运维设置中配置检查间隔。未保存过运行时设置的实例默认 30 秒；已有实例保留原配置，可手动调整。

同一规则持续超限时只创建一次告警；数量回落到阈值内后自动恢复，再次超限时受冷却时间限制（默认 10 分钟，从上次触发计算）。通知在后台告警任务中发送，不阻塞模型请求。

告警详情显示各渠道、各收件人的发送结果。失败最多重试 2 次，分别在前次尝试后约 1、2 分钟进入下一次检查；成功的目标不会因为其他目标失败而再次发送。重试状态持久化，重启后仍受总计 3 次尝试限制，已恢复事件的失败通知也可继续重试；重试范围为最近 24 小时。关闭规则或对应通知渠道会停止发送。

## 升级

后端启动时自动执行 `255_ops_alert_qq.sql`，为规则增加默认关闭的 QQ 通知开关。现有告警规则的阈值、模型范围和邮件设置不变。升级后需在后台创建并保存新规则，配置收件邮箱或 QQ 机器人后才会发送通知。
