# 上游错误条数告警（邮件 / QQ群）

在「运维监控 → 告警规则」点击「添加 502/503 告警」，可快速创建规则：

- 默认统计最近 5 分钟的上游 502、503 错误，合计超过 20 条时触发，即至少 21 条。
- 阈值、状态码、统计窗口、平台、分组、持续时间、冷却时间均可修改。窗口支持 1～1440 分钟。
- 「持续时间」为 0 时，首次检查满足条件就触发；大于 0 时需连续满足条件。
- 「排除模型」支持从使用记录中搜索，也支持手动输入多个名称。按用户请求的模型名精确匹配，区分大小写；模型映射不会改变排除结果。旧记录没有请求模型名时使用原始 model 字段。
- 统计采用运维上游错误列表口径：优先使用上游状态码，包含同步、流式和列表中可见的已通过重试恢复的上游错误；每条日志计一次，不展开内部重试明细，不计入业务限制类错误。排除模型不计入总数和状态码汇总。

例如，5 分钟内有 30 条错误，其中排除模型产生 12 条，实际计数为 18，不触发默认告警。

## 通知设置

邮件：在系统设置中配置 SMTP，在运维设置中启用预警邮件并添加收件邮箱，在规则中勾选「发送邮件通知」。可以使用系统设置中的邮件测试功能验证 SMTP。

QQ群：在「运维设置 → QQ群机器人通知」配置支持 OneBot v11 HTTP API 的机器人（如 NapCat）：

1. 填写机器人 HTTP 接口的**基础地址**，如 `http://127.0.0.1:3000`，系统会调用 `/send_group_msg`。
2. 填写目标群号和访问令牌，开启 QQ 通知并单独保存。令牌不回显；编辑时留空保留，勾选清除可删除。
3. 点击「保存并发送测试通知」验证连接，然后在告警规则中勾选「发送QQ群通知」。

基础地址必须能从 Sub2API 后端访问。容器内的 `127.0.0.1` 指向容器自身，机器人在另一容器时应使用对应服务地址。机器人需保持在线并具有目标群的发送权限。

邮件和 QQ 可以分别开启，也可以同时开启。QQ 配置在自己的卡片中单独保存。

## 检查与防重复

在运维设置中配置检查间隔。未保存过运行时设置的实例默认 30 秒；已有实例保留原配置，可手动调整。

同一规则持续超限时只创建一次告警；数量回落到阈值内后自动恢复，再次超限时受冷却时间限制（默认 10 分钟，从上次触发计算）。通知在后台告警任务中发送，不阻塞模型请求。

告警详情显示各渠道、各收件人的发送结果。失败最多重试 2 次，分别在前次尝试后约 1、2 分钟进入下一次检查；成功的目标不会因为其他目标失败而再次发送。重试状态持久化，重启后仍受总计 3 次尝试限制，已恢复事件的失败通知也可继续重试；重试范围为最近 24 小时。关闭规则或对应通知渠道会停止发送。

## 升级

后端启动时自动执行 `255_ops_alert_qq.sql`，为规则增加默认关闭的 QQ 通知开关。现有告警规则的阈值、模型范围和邮件设置不变。升级后需在后台创建并保存新规则，配置收件邮箱或 QQ 机器人后才会发送通知。
