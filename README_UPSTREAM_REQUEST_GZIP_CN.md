# 上游请求 gzip 压缩

管理员在 OpenAI API Key 账号的创建/编辑窗口开启「压缩上游请求（gzip）」。对应 `accounts.extra.openai_request_gzip=true`，默认关闭。只有已确认能解压 gzip 请求的上游才应开启；关闭即可恢复原始 JSON 上传。

该选项作用于 OpenAI 网关的 HTTP 生成请求，标准转发与透传共用同一处理入口。OAuth、插件处理的请求和 WebSocket 帧不受影响。它减少上传数据量，不修改提示、历史、工具参数、模型或推理档位，也不减少模型实际处理的 token 数。

仅压缩 128 KiB 至 32 MiB、长度已知且可重放的 POST JSON 请求，使用 gzip BestSpeed。实际体积至少缩小 5% 才采用压缩结果。已有编码、消息签名/摘要、分块上传或 trailer 的请求跳过。压缩失败保留原始请求；本功能不新增因压缩被拒绝而自动重发原文的逻辑，原有网关重试和故障转移策略保持不变。

用量日志的阶段明细增加「上游请求原始大小」和「上游请求发送大小」，单位为字节，不含 HTTP 头和 TLS 开销。可结合发送耗时验证收益。未知长度不记录，重试以最后一次尝试为准。字段位于现有 `request_timings` JSON 中，无需数据库迁移。

## 验证记录

2026-11-24 北京时间，在生产服务器向深空渠道发出不含 model 的合成 JSON，仅触发参数校验，没有调用模型。原始 2,368,900 字节，gzip 370,004 字节，减少 84.4%。HTTP/2 两轮上传加参数校验响应总耗时：原始 0.871/0.889 秒，gzip 0.248/0.257 秒。两种编码均返回 `400 model is required`。

这是合成请求的传输对照，不能推算真实会话整体提速比例，也不证明此前 35 秒上传的根因。上线后应先仅对已验证渠道开启，观察真实长请求的体积、发送耗时、首响应及错误率。

### 2026-11-27 复核

从生产服务器向 426 号账号所用上游发送不含 `model` 的合成代码上下文，通过 HTTP/2 按原文、gzip、gzip、原文的顺序对照。四次均返回 `400 model is required`，未调用模型，也未发送用户会话内容。

| 编码 | 请求体字节数 | 上传及参数校验响应总耗时 |
| --- | ---: | --- |
| 原文 | 2,469,790 | 1.172 / 1.057 秒 |
| gzip（level 1） | 691,938 | 0.558 / 0.539 秒 |

合成样本传输体积减少 71.98%，两次平均总耗时约减少 50.8%。该探测验证了 gzip 请求的参数校验路径；尚未验证压缩后真实模型生成请求的端到端行为，不能据此承诺生产请求按相同比例提速。

复核时，运行中的服务二进制不包含 `openai_request_gzip` 开关和请求体大小指标，426 号账号也未设置该开关，因此目前线上尚未应用这项优化。上线需要部署包含本实现的程序，再仅对已验证的账号启用，并观察真实请求的原始/发送大小、发送耗时、首字耗时及错误率。gzip 只减少传输体积，不减少上下文 token 数或模型计算量。

### 2026-11-28 真实生成与缓存对照

北京时间 2026-11-27 23:59:59 至 2026-11-28 00:00:40，从生产服务器直接请求 426 号账号的 `/v1/responses`。使用 `gpt-6-astra`、`reasoning.effort=high`、HTTP/2 SSE，固定同一份合成上下文、`prompt_cache_key` 和 `session_id`，依次发送原文、gzip、原文。三次 JSON 完全一致；解压一致性已校验，每次最多输出 128 token。

| 请求 | 发送字节数 | 输入 token | 缓存命中 token | 命中比例 | 输出 token | 总耗时 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 原文，首次请求 | 174,400 | 63,885 | 0 | 0% | 8 | 2.821 秒 |
| gzip，复用缓存 | 50,255 | 63,885 | 63,744 | 99.78% | 8 | 1.674 秒 |
| 原文，复用缓存 | 174,400 | 63,885 | 63,744 | 99.78% | 8 | 1.815 秒 |

三次均返回 HTTP 200、`response.completed` 和相同的 `GZIP_CACHE_OK` 回复。gzip 减少 71.18% 的请求体字节，成功命中原文建立的缓存，切回原文后命中数不变。本次真实生成对照未观察到压缩导致缓存命中下降。首次请求与后两次的耗时差包含缓存收益；不能将其全部归因于压缩，单次热缓存耗时差也不足以推断长期提速比例。

本次直接测试上游，未启用线上压缩配置。测试只包含合成数据，服务器临时样本已清理。结构化结果见 [测试记录](docs/diagnostics/2026-11-28-upstream-gzip-cache.json)，不含密钥或用户会话内容。

### 2026-11-28 本地边界与集成复核

合并远程 `main`（`82f15a9dc`）后，后端压缩、请求计时和插件路由专项测试通过；账号创建/编辑、用量展示及语言键检查共 181 项前端测试通过，前端 `vue-tsc --noEmit` 类型检查通过。

新增验证覆盖实际 128 KiB 下界和 32 MiB 上界及其相邻字节大小，确认压缩与跳过时内容均不变；重放数据读取失败时，原始请求体、长度及编码保持不变。通过本地 TLS HTTP/2 服务验证真实 gzip 解压、SSE 首事件可在响应完成前读取、缓存键原样传输，以及同一转发服务内账号开关隔离和 OAuth 跳过行为。原有测试同时覆盖 307 重定向重放、重复压缩跳过及不适用请求的原文保留。

上述结果不能保证所有第三方上游均支持 gzip。上游拒绝 gzip 时，本功能不会自行降级并重发原文；请求仍按现有错误和故障转移策略处理。应仅对已验证的账号启用。
