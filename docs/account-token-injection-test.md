# 账号注入量检测

管理员可在 **账号管理 → 测试账号 → 测试模式 → 注入量检测** 中，选择或手动填写模型 ID，测试指定账号的固定额外输入 token。首版支持 OpenAI 平台的文本账号，不需要填写额外 API Key，也不需要数据库迁移。

## 使用方式

1. 打开目标账号的测试窗口，选择“注入量检测”。
2. 选择模型，或在模型选择框中输入完整模型 ID。账号配置的模型映射仍生效，结果显示请求模型和实际出站模型。
3. 选择协议：默认跟随账号配置；API Key 账号可指定 Responses 或 Chat Completions，OAuth 账号只支持 Responses。
4. 点击“开始检测”。面板逐次展示本地输入、上游总输入、额外输入、缓存读取/写入、首字时间、总耗时及原始 usage。
5. 完成后可复制 JSON 报告。停止检测、关闭面板或切换账号会取消请求；已经发出的请求仍可能产生费用。

## 检测方法

同一个账号连续发送五次独立的最小文本请求：固定测试正文分别追加 0、256、1024、4096、4096 个重复文本单元。最后一次与第四次相同，用于检查稳定性及观察缓存。请求不携带对话历史和工具；OAuth 必要的短 instructions 也计入本地文本 token。

本地使用项目现有分词器，按出站模型选择编码。前四次拟合：

    上游报告的总输入 = 斜率 × 本地文本 token + 固定额外输入

只有以下条件同时满足，才显示截距作为估算值：

- 五次请求均正常完成，且具有合法的最终输入用量。
- 斜率与 1 的偏差不超过 0.05。
- 最大拟合误差不超过 32 token。
- 两次重复输入的上游总输入差不超过 32 token。
- 上游返回的非空模型名称一致。
- 截距不低于 -32 token；允许范围内的负值按 0 展示。

条件不满足则标记“无法可靠估算”，显示具体原因和样本，不输出确定估值。上游失败、流中断、缺少最终用量、计数非法或响应超限会停止检测。

OpenAI 协议的总输入已包含缓存读取，计算额外输入时不再加一次缓存。缓存数只作为明细显示；如果缓存读取和写入之和超过总输入，则拒绝按该口径估算。

## 如何解读

“固定额外输入”可能包含正常消息包装、系统提示词、工具定义、其他上游处理或 usage 统计偏差。它不能证明隐藏提示词的具体内容，也不能证明上游报告的 usage 真实。少量额外 token 属于正常协议开销；不应据此直接认定作弊或恶意注入。

检测直接使用所选账号的凭据、模型映射、代理和既有传输路径；影子账号使用其绑定母账号凭据。它不经过分组调度，也不复现用户完整会话或网关正常转发中的所有提示词处理。结果用于比较同一协议下的账号/模型，不代表任意实际请求的精确增量。

首字时间统计首次非空可见文本增量；非流式 JSON 响应没有可测的首字时间，显示为空。首字慢并不能单独证明注入量大。

## 运行边界

- 管理员接口：`POST /api/v1/admin/accounts/:id/token-injection-test`。
- 请求体：`{"model_id":"gpt-6-astra","protocol":"auto"}`；协议可为 `auto`、`responses`、`chat`。
- SSE 事件：`injection_start`、`injection_progress`、`injection_sample`、`injection_complete` 或 `error`。
- 固定所选账号，不进行账号切换、自动重试或普通连通性测试的账号恢复操作。
- 每个服务进程内，同一账号最多运行一个注入量检测。
- 单次请求超时 45 秒，整个检测最多 3 分钟；上游响应读取上限 2 MiB。
- 会消耗上游额度，但不生成用户扣费记录。不自动保存检测历史；需要保留结果时复制报告。

## 验证

后端单元测试覆盖固定账号与模型映射、Responses/Chat 用量、缓存不重复计数、OAuth 最小请求、影子凭据解析、异常/截断响应、取消、并发限制和回归判定。前端测试覆盖 SSE 分片与 UTF-8、错误与取消、估算结果和报告展示、切换模型后丢弃旧结果、测试窗口入口及中英文文案完整性。
