# OpenAI 低延迟备用会话池

## 配置入口

功能采用两级手动开关，均默认关闭：先在系统设置开启“OpenAI 低延迟备用会话池”总开关，再在账号创建或编辑页，为 OpenAI 的 API Key（接口密钥）账号开启“低延迟备用会话”。未保存过总开关的已有部署也保持关闭。每个账号分别配置探测模型，每行一个，默认是 gpt-6-sol，最多 20 个。未开启的账号不产生备用会话；OAuth（授权登录）账号不提供后台探测候选。

系统设置中的“OpenAI 低延迟备用会话池”配置：

| 设置 | 默认值 | 范围与作用 |
| --- | --- | --- |
| 备用池总开关 | 关闭 | 关闭时沿用原调度和原首字慢按需探测，不运行备用池补充或领取 |
| 全局空闲备用会话数 | 6 | 1–100，所有启用账号、模型和传输方式合计，不是每账号各准备 6 个 |
| 后台探测并发 | 6 | 2–20，单轮实际数量不超过当前缺口 |
| 探测结果复用保留时间 | 600 秒 | 1–3600 秒，按保存值计算新候选有效期 |

账号配置保存在 Extra（附加配置）的 openai_session_pool_enabled 和 openai_session_pool_models 字段。全局总开关是 openai_session_pool_enabled，全局目标设置是 openai_session_pool_size。后台并发与复用时间沿用原有首字慢切换设置字段，界面已移至备用池区域；慢切换开关不控制后台备用池。

## 探测与领取

仅总开关开启时，后台补足目标，每 5 秒检查一次，领取后也会唤醒补充。多个实例通过共享缓存中的原子租约协调补充，不会各自准备一整池。探测使用合成测试输入，不发送真实用户上下文，占用账号正常并发槽位并消耗上游额度，不记入用户请求账单。

只有探测成功且首字严格低于 10 秒的会话可入池。低于 5 秒的结果可以先入池并被领取，无须等待同轮其余请求；其余合格结果等该轮结束后按首字速度排序。每次补充最多 5 轮，仍不足时退避 30 秒，再由后台尝试补足。

新对话首次请求优先独占领取最快的适用候选，沿用探测的上游会话头与 prompt_cache_key（缓存亲和标识）。领取不要求用户请求模型与探测模型相同：账号的模型白名单允许当前请求模型即可，未设置模型限制时沿用原有允许所有模型的规则；实际调用按用户请求模型及现有渠道、账号模型映射处理，不替换成探测模型。后续请求、更换模型或连接方式后仍沿用已建立的对话绑定；模型和账号权限继续按正常调度校验。首次池空、无权限或无兼容候选时，按原有调度处理，允许未探测线路，不要求用户等待或重连。已经开始走普通线路的对话不会因池后来补足而再次被当成新对话。

候选共享按调用方当前分组的账号权限判断，与候选来源分组无关。领取和首次发送前校验账号对当前请求模型的支持情况，并继续校验传输方式、账号启用状态及凭据指纹；候选的原探测模型必须仍在该账号配置的探测列表中。修改账号凭据、代理、探测模型或关闭探测会使未使用的旧候选不能再领取；仅关闭账号级探测不会主动打断已经使用该会话的用户。总开关关闭后，新请求恢复原模式；已经发送的在途请求正常收尾，未使用的备用结果不再分配。

未发出用户内容的预占失败后可归还；在发送前会将候选标记为独占。之后即使请求失败，也不会再把该会话分享给其他用户。只有实际候选上的用户请求成功、发送的会话和租约与目标一致时，才记录接管成功。预热成功本身不算接管成功。

候选一旦独占，待切换期限不再使它自动退回旧线路；失败重试仍沿用同一上游会话。并发请求发现候选已被另一请求成功消费时，会重新确认对话归属，继续使用已接管的会话。无法读取或保存必要会话状态时明确返回临时不可用错误，避免把缓存故障当作新对话而悄悄换线路。

已独占会话的工具结果和响应引用可以继续沿用，不再次要求首次迁移所需的完整历史；工具回传仍不计慢，也不单独确认为用户接管成功。普通故障转移发送前必须确认新线路已保存，保存失败或并发请求已改为其他线路时停止发送；并发请求已保存同一普通线路时允许继续。

兼容旧状态时，旧绑定只允许一个线程原子认领；新状态键指向同一份绑定，不复制出多个可分别修改的私有会话。迁移写入失败后，同线程可以重试，其他线程不能继承已经被认领的绑定。活跃请求会同时续期实际绑定和迁移入口，保持两小时的有效期；已经独占但尚未确认成功的绑定也会续期。必要续期失败时返回临时不可用错误，不继续发送。

## 与首字慢切换的关系

备用池总开关关闭时，保留原有首字慢按需探测、结果复用和切换流程，仍由原首字慢开关控制。两个开关都关闭时不探测、不接管，也不改变出站会话标识。关闭账号级开关只停止该账号提供新候选，原有账号调用资格不变。

原首字慢切换开关、首字阈值、可选最低输出 TPS（每秒输出词元数）、连续慢次数和冷却规则保留。填写最低 TPS 后，必须首字达到慢阈值且 TPS 低于最低值，才计为慢请求。

备用池总开关开启时，达到切换条件后只领取同一个后台池，不启动独立探测。没有授权且兼容的候选就保留原线路。已有慢对话继续采用原来的安全接管方式：在用户消息边界发出重试或重连信号，要求完整上下文，不能拿旧线路的增量引用直接冒充完整上下文。新对话直接使用备用会话，不需要此重连步骤。

范围是现有 Codex Responses（响应接口）的普通、流式和长连接入口；需要稳定的用户会话标识。上下文压缩请求沿用已经建立的绑定，不领取新候选、不计慢切换。聊天补全、图像及其他专用入口沿用原流程。速度筛选测量的是首字延迟，不是回答质量评测。

## 诊断事件

后台补充和领取诊断使用组件 `openai.session_pool`，写入应用日志，不写入“首字慢账号切换”记录。日常级别只记录实际补充批次汇总和领取失败；每 5 秒的空闲检查、单路探测、候选入池等明细放在 `debug`（调试）级别。功能关闭时不新增备用池日志或后台探测。

| 事件 | 级别与含义 |
| --- | --- |
| `openai.session_pool_refill_completed` | 每次已取得补充租约的任务结束时汇总一次：目标数、起始空闲数、最后观察的空闲数、轮数、探测次数、合格或失败原因分布、实际入池数、未入池数、耗时及退避时间；轮次耗尽仍不足、缓存失败使用警告级别，其余为普通级别 |
| `openai.session_pool_refill_started` / `openai.session_pool_refill_skipped` | 调试级别；开始时包含并发与候选保留秒数；跳过时区分池已满、无可探测线路、已有补充任务或退避中 |
| `openai.session_pool_probe_completed` | 调试级别；记录账号、模型、协议、首字是否测得、首字耗时、探测响应 HTTP 状态、最终原因。`success`（探测成功）不等于 `qualified`（满足入池条件），例如成功但首字达到 10 秒仍不合格；response_status 是网关探测接收端的响应状态，可能由网关转换，不保证等于上游原始状态；零表示未写出响应状态 |
| `openai.session_pool_candidate_publish` | 调试级别；合格结果是否真正写入池、候选编号、上游会话摘要；合格但池已满、补充租约失效或缓存写入失败时不会计入已入池数量 |
| `openai.session_pool_reservation` | 领取未成功为普通级别，账号列表读取失败或缓存失败为警告；领取成功为调试级别。记录可用账号数量、候选数量和拒绝分类计数 |
| `openai.session_pool_assignment_skipped` | 普通级别；候选已预占，但会话待切换状态未写入，已尝试归还预占。并发请求已经建立绑定也可能出现，需结合缓存日志判断 |
| `openai.session_pool_candidate_abandoned` | 普通级别；已清除待接管目标，记录原因及是否已独占。未发送的候选尝试归还，已独占候选尝试废弃；是否写入缓存以缓存失败日志为准 |
| `openai.session_pool_selection_failed` / `openai.session_pool_commit_failed` | 警告级别；目标账号选择报错、发送前无法取得候选所有权或无法保存独占状态 |
| `openai.session_pool_assigned` | 原业务事件：首次请求已预占候选，补充探测首字速度、剩余有效期及协议 |
| `openai.session_pool_assignment_completed` | 原业务事件：首次用户请求已在候选会话成功完成 |
| `openai.session_pool_candidate_discarded` | 原业务事件：已独占候选被放弃，补充具体原因 |
| `openai.ws_latency_switch_pending` / `openai.ws_latency_switch_completed` | 保留原慢切换的待切换、切换成功事件 |

### 常用原因码

| 场景 | 原因码与含义 |
| --- | --- |
| 探测结果 | `qualified` 合格；`first_token_too_slow` 首字达到或超过 10 秒；`probe_timeout` 超时；`probe_canceled` 取消；`probe_http_error` 探测收到 HTTP 错误状态；`upstream_request_failed` 转发失败；`no_successful_first_token` 未取得成功首字；`upstream_session_missing` 缺少上游会话；`upstream_model_mismatch` 实际模型不符 |
| 无法开始单路探测 | `account_lookup_failed` 账号读取失败；`account_configuration_changed` 账号配置变化或不可调度；`account_request_incompatible` 账号不兼容当前探测请求；`account_slot_unavailable` 未取得账号并发槽位 |
| 补充任务 | `target_reached` 已达到目标；`probe_rounds_exhausted` 本次最多 5 轮后仍不足；`refill_lease_lost` 补充租约失效；`cache_update_failed` 缓存更新失败；`refill_canceled` 已取消；`feature_disabled` 进行中关闭功能 |
| 未开始补充 | `pool_full` 空闲池已满；`no_eligible_routes` 无可探测的账号、模型和协议组合；`refill_in_progress` 其他任务持有补充租约；`retry_backoff` 退避中 |
| 领取失败 | `pool_empty` 池空；`no_eligible_accounts` 当前分组没有符合权限、配置及调度要求的账号；`channel_pricing_restricted` 渠道价格限制；`no_matching_candidate` 有候选但不匹配当前请求，查看拒绝计数 |
| 候选拒绝分类 | `expired` 过期；`account_not_eligible` 账号不在本次可用集合；`leased` 被预占；`already_committed` 已独占；`transport_mismatch` 协议不匹配；`account_changed` 凭据或代理等配置变化；`model_not_configured` 原探测模型已不在探测列表；`invalid_latency` 首字速度不合格；`upstream_session_missing` 缺少上游会话。当前请求模型不被账号允许时，该账号会被提前排除，不计为探测模型不匹配 |
| 放弃或接管失败 | `pending_expired` 待接管过期；`incremental_context_incompatible` 旧线路的增量上下文不能交给新会话；`target_excluded` 目标已被本次调度排除；`candidate_no_longer_eligible` 候选已不符合要求；`target_unavailable` 未选到目标；`candidate_commit_failed` 未取得候选所有权；`ownership_state_not_updated` 已独占但会话状态未保存 |

### 排查顺序

1. 先查 `openai.session_pool_refill_completed`，确认是否探测、产生多少合格结果、多少真正入池。`probe_outcomes`（探测结果分布）区分速度不达标与请求失败；`published_count`（实际入池数）只在缓存更新成功后累计，不能等同于当前池剩余数。
2. 再查 `openai.session_pool_reservation`，确认当前分组有没有可用账号、候选是否全部被占用，或被模型、协议、配置变化过滤。`rejections`（拒绝计数）按每个候选首先命中的原因互斥计数；领取失败时扫描全部候选，成功时只扫描到选中位置。原子更新重试不会重复累计。
3. 需要逐路定位时临时开启调试级别，用 `refill_id`（补充批次编号）、`round`（轮次）、`probe_number`（本轮探测编号）串联；通过入池事件的 `target_result_id`（候选结果编号）关联后续预占、放弃和接管。`upstream_session_hash` 是会话摘要，不是原始会话标识。
4. 已预占但未接管，查看选择、独占、放弃原因；实际用户请求失败继续查看 `openai.latency_diagnostic` 的 `recovery_request_unsuccessful`，现已附上实际发送的候选结果编号、错误类型及超时／取消标志。只有完成事件代表用户请求成功接管。

`available_last_observed`（最后观察的空闲数）来自本次已有缓存操作的快照，不额外读取缓存。并发领取会使其与查日志时的实时数量不同。`not_published_count`（合格但未入池数）包括功能中途关闭、池已满、租约失效和缓存写入失败。

探测完成、预占及应用会话标识都不等于成功接管。后台补充不关联某个触发用户；用户侧领取、接管与慢切换事件保留用户编号、分组和请求关联信息。新增诊断不记录用户正文、工具输出、密钥、请求头、原始错误文本或原始上游会话标识，只使用固定原因码、数值和会话摘要。
