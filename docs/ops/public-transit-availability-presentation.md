# Public transit availability presentation

This rule is disabled by default. Administrators can enable or disable it under
System Settings → Feature Toggles → Public Transit using the DeepSeek / GLM
availability presentation switch. The persisted setting is
`public_transit_availability_adjustment_enabled`; only explicit `true` enables
the rule. When disabled, exports return observed availability with no adjustment
metadata. Changes apply on the next snapshot request without a restart (an
already cached V2 response can remain visible for up to 60 seconds).

The public transit snapshot applies a synthetic presentation rule only to the
existing `deepseek-v4.1-flash` and `glm-5.3` active monitor models. For each of
`availability_7d`, `availability_15d` and `availability_30d`, an observed value
below 85% is replaced with a value from the configured minimum through maximum,
in increments of 0.01 percentage points. The default interval is 88.00% through
90.00%. Values at or above 85% and other models are unchanged.

The same settings panel provides minimum and maximum percentage inputs, persisted
as `public_transit_availability_adjustment_min` and
`public_transit_availability_adjustment_max`. Both accept 0 through 100 inclusive,
with at most two decimal places, and the minimum must not exceed the maximum.
Equal bounds produce a fixed presentation value. Zero is a valid setting, not a
missing value. Missing keys use the defaults; malformed stored bounds disable
adjustment until corrected. Partial API updates preserve omitted bounds. Bounds
can be saved while the switch is off and take effect when it is enabled.

Adjusted objects include `availability_adjustment`, identifying the policy as
`synthetic_below_85_v1`, explaining that the result is not observed availability,
including the configured `display_minimum` and `display_maximum`, and preserving
original measurements in `raw_availability_7d`,
`raw_availability_15d` and `raw_availability_30d`. Consumers that require measured
availability must use these original values when the adjustment is present.

The pseudorandom value is derived from the model, period, original value and custom bounds. It
therefore remains stable across repeated requests, process restarts and V1/V2
responses until that measurement or its configured bounds change. The default
interval preserves values generated by the previous version. JSON fields remain numeric; trailing
zeroes are not guaranteed by JSON serialization. Primary monitor summaries copy
the same adjusted values and disclosure as their model entry.

Only copied public export DTOs are adjusted. Monitor histories, statuses,
timelines, latency, passive real-traffic metrics, billing, routing and account or
group configuration are unchanged. Missing monitor details do not manufacture
15-day or 30-day samples, and monitors without observations are not adjusted.
