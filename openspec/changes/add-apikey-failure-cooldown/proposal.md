# 说明
本提案为启用“使用当前服务”的渠道监控请求增加统一的账号冷却和慢响应优先级调节，并将相关参数做成可配置项。

## Why

当前需求不需要对所有 API Key 请求建立复杂的故障分类和模型级冷却链；真正需要保护的是通过当前服务发出的渠道监控探测。监控失败或持续响应过慢时，应暂时避开对应账号，同时保留可调整的运营参数，避免固定规则与实际部署不匹配。

## What Changes

- **BREAKING**：移除普通 API Key 请求、其他 API Key 类型、模型维度和故障分类维度的统一冷却触发；这些请求继续沿用原有行为。
- 在新增或编辑渠道监控时持久化“使用当前服务”开关；只有管理员点击该操作并保存后，该监控探测才进入本能力。
- 为带监控标记的探测请求增加内部上下文标识。请求的所有失败结果（HTTP 错误、网络错误、空响应、超时或其他失败）统一按账号进入冷却链，不区分模型、故障类型或 API Key 细节。
- 将账号冷却阶梯统一为五档，默认值为 `2`、`5`、`30`、`60`、`120` 分钟；连续失败事件按阶梯推进，达到末档后保持末档。
- 冷却阶梯可在管理端配置，配置页提供“恢复默认值”操作；非法值不得保存，运行时继续使用最近一次有效配置。
- 增加渠道监控慢响应处理：探测响应时间超过阈值时，账号优先级临时增加一个配置的增量；同一临时周期最多增加配置次数，默认最多 `+3` 次。
- 下一次探测响应时间不超过阈值时立即恢复账号原优先级；从第一次增加开始计时，达到默认 `1` 小时的自动恢复时长后也恢复原值并清理临时状态。
- 慢响应阈值、优先级增量、最多增加次数和自动恢复时长均可配置，并与冷却阶梯一起提供恢复默认值。

## Capabilities

### New Capabilities

- `apikey-failure-cooldown`：定义渠道监控标记、账号级失败冷却、可配置五档阶梯、慢响应优先级临时调整及管理端配置恢复默认行为。

### Modified Capabilities

无。

## Impact

- 后端渠道监控模型、管理 API、仓储和数据库迁移：保存 `use_current_service`，并在探测请求中传递内部标记。
- 后端认证/网关与冷却协调器：仅识别带监控标记的请求；统一写入账号级冷却状态并在发送前避让。
- 账号调度与缓存：保存临时优先级原值、已增加次数和首次增加时间，支持并发更新、自动恢复及调度快照同步。
- 管理端系统设置 API、设置页面和中英文文案：提供冷却与慢响应参数编辑、校验、保存、加载和恢复默认值。
- 兼容性：不新增模型级冷却语义；未使用当前服务的监控和所有普通 API Key 请求不进入新冷却链。数据库仅增加监控开关字段及必要迁移。
- 测试：覆盖开关持久化、请求标记、账号级失败阶梯、并发合并、冷却恢复、优先级增加/恢复/自动超时、配置校验和前端恢复默认操作。
