# 说明
本提案将为非池模式 API Key 账号增加统一、可配置且支持高并发合并的故障冷却与调度避让能力。

## Why

当前账号级与模型级故障处理分散在 429、529、5xx、传输错误及平台专用分支中，冷却范围、连续失败升级和成功重置并不一致，导致不可用 API Key 账号可能在多个分组中被反复选中。需要一个统一决策入口，在保留现有调度存储与故障转移安全边界的同时，让可恢复故障可靠进入冷却并在到期后自动恢复。

## What Changes

- 为 `type=apikey` 且非池模式的账号引入统一故障冷却协调器，集中完成适用范围检查、故障分类、连续失败计数、冷却决策和状态写入。
- 支持账号级及“账号＋规范化上游模型”级冷却；账号级冷却跨账号所属全部分组生效，模型级冷却不影响同账号的其他模型。
- 将 429、529、可恢复 401/403、5xx、上游传输故障、配额或余额耗尽、模型不可用、明确全局故障及无法分类故障映射到可配置冷却策略。
- 对无法分类的上游故障提供默认 `1 → 10 → 30` 分钟循环冷却；其他连续失败阶梯到达末档后保持末档。
- 在高并发下把同一活跃冷却窗口内的并发失败合并为一个冷却事件，避免一次故障突发被误计为多次连续失败。
- 在上游发送前增加共享冷却最终守卫，使新请求跨服务实例避开刚进入冷却、但调度快照尚未完成传播的账号。
- 成功响应清除对应账号级及“账号＋模型”级连续失败计数；冷却状态到期后由现有调度条件自动恢复。
- 在管理后台增加版本化的系统级 API Key 故障冷却配置，提供各故障族开关、冷却阶梯和末档保持或循环方式。
- 保留账号自定义错误码与临时不可调度规则的优先级；池模式、OAuth、Setup Token 及其他账号类型继续使用现有行为。
- 明确无效 Key、令牌撤销、永久账号错误、告警、审批、冷却历史和账号错误恢复不纳入本次冷却改造，继续交由现有机制处理。

## Capabilities

### New Capabilities

- `apikey-failure-cooldown`: 定义非池模式 API Key 账号的故障分类、可配置冷却、高并发事件合并、跨分组与模型级调度避让、成功重置及自动恢复行为。

### Modified Capabilities

- 无。

## Impact

- 后端服务层：统一现有 API Key 可恢复故障的冷却入口，并接入各协议的账号调用成功与失败出口。
- 调度与故障转移：复用现有账号级、模型级候选过滤和失败账号集合，增加发送前共享冷却守卫。
- 存储：复用账号临时不可调度字段和 `model_rate_limits`，扩展模型级“只延长、不缩短”原子写入；共享缓存新增版本化冷却事件与连续失败状态，不新增数据库表或字段。
- 管理 API 与前端：新增集中式 API Key 故障冷却配置的读取、校验、更新与设置界面。
- 兼容性：现有冷却继续自然到期，原有 429/529 配置继续服务未纳入新协调器的账号类型，池模式健康熔断保持不变。
- 测试：新增策略、并发原子性、存储、跨分组调度、模型隔离、故障转移、配置界面和既有账号类型回归覆盖。
