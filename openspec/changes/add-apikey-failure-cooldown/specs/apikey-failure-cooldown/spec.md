## ADDED Requirements

### Requirement: 冷却策略适用范围与优先级
系统 MUST 仅对 `type=apikey` 且非池模式的账号应用统一故障冷却协调器。账号自定义错误码或临时不可调度规则只有在本次错误实际命中时才 SHALL 优先于系统默认策略；未启用或未命中的自定义规则 MUST NOT 跳过默认分类。

#### Scenario: 非池模式 API Key 账号进入统一协调器
- **WHEN** 一个 `type=apikey` 且未启用池模式的账号完成一次上游调用
- **THEN** 系统 MUST 通过统一协调器观察该次成功或失败结果

#### Scenario: 其他账号类型保持原行为
- **WHEN** 账号为 OAuth、Setup Token、其他非 API Key 类型或已启用池模式
- **THEN** 系统 MUST NOT 对该账号应用新的统一冷却策略
- **AND** 系统 SHALL 继续执行该账号类型的现有错误、重试与健康熔断逻辑

#### Scenario: 实际命中的账号自定义规则优先
- **WHEN** API Key 账号的自定义错误码或临时不可调度规则实际命中本次错误
- **THEN** 系统 MUST 交由现有自定义规则处理
- **AND** 统一协调器 MUST NOT 对同一次尝试重复计数或写入默认冷却

#### Scenario: 自定义规则未命中时进入默认分类
- **WHEN** API Key 账号启用了自定义规则但本次错误没有命中任何规则
- **THEN** 系统 MUST 继续执行系统默认故障分类与兜底策略

### Requirement: 明确不冷却的错误
系统 MUST 将明确属于请求、内容或客户端生命周期的问题排除在账号健康冷却之外。结束冷却判断 MUST NOT 被解释为终止整个请求；现有请求流程仍负责返回错误或处理取消。

#### Scenario: 参数错误不冷却
- **WHEN** 上游错误被可靠识别为参数、请求格式或其他客户端输入错误
- **THEN** 系统 MUST NOT 创建冷却事件
- **AND** 系统 MUST NOT 增加任何连续失败计数

#### Scenario: 内容安全拒绝不冷却
- **WHEN** 上游错误被可靠识别为内容安全拒绝
- **THEN** 系统 MUST NOT 冷却账号或模型

#### Scenario: 客户端取消或超时不冷却
- **WHEN** 请求因客户端取消或客户端自身截止时间到达而终止
- **THEN** 系统 MUST NOT 冷却所选账号
- **AND** 系统 MUST NOT 因该结果自动切换账号

#### Scenario: 上游超时与客户端超时分离
- **WHEN** 客户端仍然有效但上游发生连接、读取或首输出超时
- **THEN** 系统 MUST 将其分类为可恢复上游故障
- **AND** 系统 MUST NOT 将其误分类为客户端超时

#### Scenario: 已经下发响应后不新增冷却或重放
- **WHEN** 本次尝试发生错误前已经向客户端下发响应内容
- **THEN** 系统 MUST NOT 通过本能力新增冷却
- **AND** 系统 MUST NOT 自动重放该请求

#### Scenario: 只有响应头或保活时仍可超时冷却
- **WHEN** 本次尝试只向客户端写入 HTTP 响应头、空白内容或流式保活，尚未写入有效应用内容
- **AND** 尝试达到首个有效内容期限
- **THEN** 系统 MUST 将其作为上游超时创建冷却
- **AND** 系统 MUST 继续根据实际下游提交状态决定是否安全重放

### Requirement: 所有受管请求具有 29 秒首个有效内容期限
系统 MUST 对所有经统一协调器管理的非池模式 API Key 上游尝试执行固定 29 秒首个有效内容期限。期限 MUST 绑定单个账号尝试；达到期限时 MUST 取消当前上游尝试、按账号级瞬时上游故障创建冷却，并 MUST NOT 直接取消仍可安全故障转移的原始客户端请求。

#### Scenario: 非流式请求 29 秒无有效内容
- **WHEN** 非流式上游尝试在发送后 29 秒内没有产生非空应用响应体
- **AND** 客户端请求仍然有效
- **THEN** 系统 MUST 取消该账号的当前上游尝试
- **AND** 系统 MUST 按账号级 `transient_upstream` 创建冷却

#### Scenario: 流式保活不解除期限
- **WHEN** 流式上游在 29 秒内仅产生响应头、空写入或 SSE 注释保活
- **THEN** 系统 MUST NOT 把这些信号视为有效内容
- **AND** 系统 MUST 在期限到达时取消当前账号尝试并创建账号级冷却

#### Scenario: 首个有效应用内容解除期限
- **WHEN** 上游在 29 秒内产生首个非保活应用响应体、流式应用帧或 WebSocket 应用帧
- **THEN** 系统 MUST 解除本次尝试的首个有效内容期限
- **AND** 后续长时间流式传输 MUST NOT 因该期限被取消

#### Scenario: 超时后遵守安全故障转移
- **WHEN** 当前账号因首个有效内容超时进入冷却
- **AND** 现有调用链确认请求安全可重放且仍有候选账号
- **THEN** 系统 SHALL 排除该账号并尝试下一候选
- **AND** 不安全重放时系统 MUST 尽快向调用方返回 504

#### Scenario: 当前服务渠道监控不豁免
- **WHEN** 渠道监控使用当前服务地址和用户自己的 Key 发起探活请求
- **AND** 内层网关选中的账号在 29 秒内没有有效内容
- **THEN** 该账号 MUST 进入相同账号级冷却链路
- **AND** 渠道监控在自身 35 秒响应头期限内仍无最终响应时 MUST 将本次探活判定为错误

### Requirement: 永久凭据错误委托现有机制
统一冷却协调器 MUST NOT 把明确无效 Key、令牌撤销或其他已由现有机制认定的永久凭据错误转换为临时冷却，也 MUST NOT 新增相关告警或错误恢复行为。

#### Scenario: 明确无效 Key 不进入冷却
- **WHEN** 错误被可靠识别为无效 API Key 或令牌已撤销
- **THEN** 统一协调器 MUST NOT 创建冷却事件
- **AND** 系统 SHALL 继续使用现有账号错误处理逻辑

### Requirement: 系统级冷却配置
系统 MUST 提供版本化的系统级 API Key 故障冷却配置。每个可恢复故障族 MUST 能独立启用或禁用，并 MUST 支持正整数秒数组形式的冷却阶梯以及“保持末档”或“循环阶梯”模式。账号级或模型级作用域 SHALL 由故障语义固定，MUST NOT 允许管理员任意改写。

默认启用的策略 MUST 为：

| 故障族 | 默认作用域 | 默认冷却阶梯 | 默认模式 |
|---|---|---:|---|
| 429 且有可靠上游时间 | 账号 | 到上游时间 | 上游时间优先 |
| 429 无重置时间 | 账号 | 60、300、900 秒 | 保持末档 |
| 529 或明确过载 | 账号＋模型；无模型或明确整号时为账号 | 60、300 秒 | 保持末档 |
| 500/502/503/504、上游连接超时、连接重置、空响应 | 账号 | 30、120、600 秒 | 保持末档 |
| 明确临时并发或临时访问限制 403 | 账号 | 300 秒 | 保持末档 |
| 明确账号被封或永久权限失效 | 账号 | 300 秒 | 保持末档 |
| 未明确为无效 Key 的其他 401 | 账号 | 1800 秒 | 保持末档 |
| 配额或余额耗尽 | 账号 | 3600 秒 | 保持末档 |
| 模型不存在或不支持 | 账号＋模型 | 1800 秒 | 保持末档 |
| 明确全局故障 | 当前失败账号 | 1800 秒 | 保持末档 |
| 无法分类的上游故障 | 账号 | 60、600、1800 秒 | 循环阶梯 |

#### Scenario: 未保存配置时使用安全默认值
- **WHEN** 系统尚未保存 API Key 故障冷却配置
- **THEN** 配置读取接口和运行时协调器 MUST 使用本要求定义的默认策略

#### Scenario: 配置运行时生效
- **WHEN** 管理员保存一份合法的新冷却配置
- **THEN** 后续创建的冷却事件 MUST 使用新配置
- **AND** 服务 MUST NOT 要求重启

#### Scenario: 非法配置被拒绝
- **WHEN** 配置包含空阶梯、非正数时长、未知阶梯模式或不支持的结构版本
- **THEN** 管理 API MUST 拒绝保存该配置
- **AND** 运行时 MUST 继续使用最近一次有效配置

#### Scenario: 配置读取失败时安全回退
- **WHEN** 运行时暂时无法读取设置存储
- **THEN** 系统 MUST 优先使用最近一次有效配置
- **AND** 从未读取成功时 MUST 使用内置默认值

### Requirement: 已知故障分类与冷却决策
系统 MUST 在请求级排除和永久凭据委托之后，根据稳定状态码、结构化供应商错误字段、受限响应头及严格错误模式分类已知可恢复故障。不同具体状态码属于同一故障族时 MUST 共用连续失败计数。

#### Scenario: 429 遵从可靠上游时间
- **WHEN** API Key 账号返回 429 且提供未来有效的 `Retry-After` 或可靠重置时间
- **THEN** 系统 MUST 将账号冷却到上游指定时间
- **AND** 本地固定阶梯 MUST NOT 缩短该时间

#### Scenario: 429 无可靠重置时间
- **WHEN** API Key 账号返回 429 且没有可用重置时间
- **THEN** 系统 MUST 按账号作用域依次使用 60、300、900 秒冷却
- **AND** 第三次之后 MUST 保持 900 秒末档

#### Scenario: 已过期或无效的上游时间回退
- **WHEN** 429 携带的重置时间无效、无法解析或不晚于当前时间
- **THEN** 系统 MUST 使用 429 无重置时间阶梯

#### Scenario: 模型过载只冷却对应模型
- **WHEN** 错误为 529 或明确“过载、稍后重试”且最终上游模型可确定
- **THEN** 系统 MUST 按“账号＋最终上游模型”作用域依次使用 60、300 秒冷却
- **AND** 同账号其他模型 MUST 保持可调度

#### Scenario: 整号过载使用账号作用域
- **WHEN** 过载错误没有模型上下文或可靠表明账号整体不可用
- **THEN** 系统 MUST 按账号作用域使用 60、300 秒冷却

#### Scenario: 瞬时上游故障共享阶梯
- **WHEN** 同一账号连续收到 500、502、503、504、上游连接超时、连接重置或空响应中的任意组合
- **THEN** 系统 MUST 将这些结果归入同一账号级故障族
- **AND** 系统 MUST 依次使用 30、120、600 秒冷却并保持末档

#### Scenario: 明确临时 403 冷却账号
- **WHEN** 403 内容可靠表明临时并发或临时访问限制
- **THEN** 系统 MUST 冷却当前账号 300 秒

#### Scenario: 明确账号被封或永久权限失效短暂冷却
- **WHEN** 错误可靠表明账号被封或权限永久失效但不属于明确无效 Key 或令牌撤销
- **THEN** 系统 MUST 冷却当前账号 300 秒

#### Scenario: 其他 401 冷却账号
- **WHEN** API Key 账号返回 401 且无法可靠认定为无效 Key 或令牌撤销
- **THEN** 系统 MUST 冷却当前账号 1800 秒

#### Scenario: 配额或余额耗尽
- **WHEN** 错误可靠表明账号配额或余额耗尽
- **THEN** 系统 MUST 冷却当前账号 3600 秒

#### Scenario: 模型不存在或不支持
- **WHEN** 错误可靠表明账号不存在或不支持最终上游模型
- **THEN** 系统 MUST 仅冷却该“账号＋最终上游模型”1800 秒

#### Scenario: 明确全局故障只冷却实际失败账号
- **WHEN** 上游错误可靠表明全局故障
- **THEN** 系统 MUST 冷却本次实际失败账号 1800 秒
- **AND** 系统 MUST NOT 创建平台级、分组级或模型共享熔断

### Requirement: 无法分类故障循环兜底
在全部明确分类与排除规则之后，仍可归因于上游但无法判断具体故障类型的错误 MUST 使用账号级循环兜底。兜底阶梯 MUST 默认为 60、600、1800 秒，并在第四个连续冷却事件重新从 60 秒开始。

#### Scenario: 兜底阶梯循环
- **WHEN** 同一账号依次产生四个无法分类且中间没有成功的独立冷却事件
- **THEN** 四个事件的冷却时长 MUST 依次为 60、600、1800、60 秒

#### Scenario: 明确不冷却错误不进入兜底
- **WHEN** 错误已经被识别为参数错误、内容安全拒绝、客户端取消或客户端自身超时
- **THEN** 系统 MUST NOT 将其作为无法分类故障冷却

### Requirement: 高并发失败按冷却事件合并
系统 MUST 以冷却事件而不是请求数量计算连续失败。账号级事件键 MUST 由账号和故障族组成；模型级事件键 MUST 由账号、最终上游模型和故障族组成；事件键 MUST NOT 包含分组。

#### Scenario: 一百个并发失败只增加一次
- **WHEN** 100 个已经在途的请求对同一作用域产生相同故障且首个失败创建的冷却仍有效
- **THEN** 系统 MUST 只创建一个冷却事件
- **AND** 连续失败次数 MUST 只增加一次
- **AND** 后续 99 个失败 MUST NOT 缩短或重复持久化该冷却

#### Scenario: 冷却结束后的下一次失败升级
- **WHEN** 当前冷却已经结束且同一作用域尚未出现有效成功
- **AND** 下一次调用再次产生同一故障族失败
- **THEN** 系统 MUST 创建新的冷却事件
- **AND** 连续失败次数 MUST 增加一次并选择下一阶梯

#### Scenario: 多实例共享同一冷却事件
- **WHEN** 多个服务实例并发观察同一作用域的故障
- **THEN** 系统 MUST 通过共享原子状态得到一致的事件代次、连续次数和截止时间

#### Scenario: 不同故障族独立计数
- **WHEN** 同一账号先发生 429 无重置时间，随后发生瞬时 5xx 故障
- **THEN** 两个故障族 MUST 分别维护连续失败次数

### Requirement: 成功响应安全重置连续失败
有效上游成功 MUST 清除该账号的账号级连续失败计数以及本次最终上游模型的模型级连续失败计数，但 MUST NOT 提前缩短已经持久化的冷却。冷却创建前已经在途的旧成功 MUST NOT 清除较新的冷却事件。

#### Scenario: 冷却结束后的成功清零
- **WHEN** 冷却结束后通过发送前守卫放行的新尝试获得有效上游成功
- **THEN** 系统 MUST 清除该账号的账号级连续失败计数
- **AND** 系统 MUST 清除该账号与本次最终上游模型的模型级连续失败计数

#### Scenario: 旧在途成功不能覆盖新事件
- **WHEN** 一个尝试在冷却事件创建前已经发送，并在冷却创建后才返回成功
- **THEN** 系统 MUST NOT 用该旧成功清除新冷却事件或其连续失败次数

#### Scenario: 成功不提前解除已生效冷却
- **WHEN** 系统观察到一个可接受的成功结果但对应持久化冷却尚未到期
- **THEN** 系统 MUST NOT 缩短持久化冷却截止时间

### Requirement: 账号级与模型级冷却持久化
账号级冷却 MUST 复用账号临时不可调度状态，模型级冷却 MUST 复用 `extra.model_rate_limits`。两种写入都 MUST 采用“只延长、不缩短”语义，并 MUST 触发现有账号调度快照同步和账号变更传播。

#### Scenario: 账号级冷却跨全部分组生效
- **WHEN** 一个同时绑定分组 A 和分组 B 的账号进入账号级冷却
- **THEN** 分组 A 与分组 B 的调度候选都 MUST 排除该账号

#### Scenario: 模型级冷却不影响其他模型
- **WHEN** 账号与模型 M1 的组合进入模型级冷却
- **THEN** 调度模型 M1 时 MUST 排除该账号
- **AND** 调度模型 M2 时该账号 SHALL 在满足其他条件时保持可用

#### Scenario: 较短并发写入不能覆盖较长冷却
- **WHEN** 同一作用域已有更晚的冷却截止时间
- **AND** 并发请求尝试写入更早的截止时间
- **THEN** 持久化状态 MUST 保留较晚截止时间

#### Scenario: 到期后自动恢复
- **WHEN** 账号级或模型级冷却到达截止时间且不存在其他不可调度条件
- **THEN** 现有调度查询 MUST 自动重新接纳对应账号或“账号＋模型”
- **AND** 系统 MUST NOT 要求后台解除任务

#### Scenario: 重启后冷却仍有效
- **WHEN** 服务在冷却期间重启
- **THEN** 数据库中的冷却截止时间 MUST 继续被调度器遵守

### Requirement: 发送前共享冷却守卫
系统 MUST 在最终账号选择完成后、真正发送上游请求前检查共享账号级和模型级冷却状态。守卫 MUST 返回事件代次供成功与失败状态转换使用，并 MUST 有界地重新选择被冷却账号的替代候选。

#### Scenario: 快照尚未传播时阻止新发送
- **WHEN** 调度快照仍包含一个刚进入共享冷却的账号
- **THEN** 发送前守卫 MUST 阻止向该账号发起新的上游请求
- **AND** 当前请求 MUST 排除该账号并尝试重新选择

#### Scenario: 冷却前已发送的请求自然结束
- **WHEN** 请求在冷却事件创建前已经发往上游
- **THEN** 系统 MUST NOT 尝试撤回该请求
- **AND** 其失败结果 SHALL 合并到当前冷却事件

#### Scenario: 共享缓存不可用时回退现有状态
- **WHEN** 发送前守卫无法读取共享缓存
- **THEN** 系统 MUST 回退到现有账号快照与最终新鲜度检查
- **AND** 缓存故障 MUST NOT 阻断全部 API 流量

### Requirement: 冷却与安全故障转移解耦
创建冷却后，系统 MUST 在当前请求中排除失败账号；是否重放或切换账号 MUST 继续服从现有安全边界。冷却本身 MUST NOT 扩大可重放范围。

#### Scenario: 安全可重放时切换账号
- **WHEN** 失败账号已进入冷却且现有请求链路确认本次请求安全可重放
- **THEN** 系统 SHALL 尝试选择同组下一个可用账号

#### Scenario: 不安全重放时停止切换
- **WHEN** 客户端已取消、响应已经开始下发或传输层明确表示请求不能安全重放
- **THEN** 系统 MUST NOT 因冷却而自动切换账号

### Requirement: 依赖故障时保持基础冷却保护
共享计数或持久化依赖出现故障时，系统 MUST 尽可能保留当前请求排除和第一档冷却，不得因为无法升级连续次数而完全跳过故障账号保护。

#### Scenario: 共享计数不可用时使用第一档
- **WHEN** 共享事件存储不可用但数据库可写
- **THEN** 系统 MUST 按对应策略第一档写入冷却
- **AND** 当前请求 MUST 排除失败账号

#### Scenario: 数据库写入失败时共享守卫继续保护
- **WHEN** 共享冷却事件已创建但数据库持久化失败
- **THEN** 发送前守卫 MUST 在共享事件有效期间继续阻止新请求使用该作用域
- **AND** 后续持久化重试 MUST NOT 重复增加连续失败次数

#### Scenario: 两类依赖均失败时保护当前请求
- **WHEN** 共享事件存储和数据库冷却写入同时失败
- **THEN** 当前请求 MUST 至少把失败账号加入本地排除集合
- **AND** 系统 MUST 记录不含密钥和完整上游响应的脱敏错误日志

### Requirement: 管理后台集中配置
管理后台 MUST 提供 API Key 故障冷却的集中配置区域，并 MUST 支持读取默认值、编辑各故障族开关与阶梯、选择保持末档或循环模式、保存及展示校验错误。现有 429/529 设置接口 MUST 保留给未纳入新协调器的账号类型。

#### Scenario: 管理员查看默认策略
- **WHEN** 管理员首次打开 API Key 故障冷却设置
- **THEN** 页面 MUST 展示本规范定义的全部默认故障族、冷却阶梯和模式

#### Scenario: 保存配置后前后端一致
- **WHEN** 管理员提交合法配置
- **THEN** 管理 API MUST 返回规范化后的配置
- **AND** 页面重新加载后 MUST 展示相同配置

#### Scenario: 旧设置接口保持兼容
- **WHEN** 旧前端或其他客户端访问现有 429/529 设置接口
- **THEN** 系统 MUST 继续提供兼容响应
- **AND** 新配置 MUST NOT 隐式改变池模式或非 API Key 账号行为

### Requirement: 错误信息最小化与脱敏
分类器和冷却状态 MUST 只处理完成分类所需的有限错误数据。系统 MUST 限制响应正文读取长度，MUST NOT 把 API Key、Authorization、完整上游响应或其他凭据写入共享缓存、冷却原因或日志。

#### Scenario: 冷却原因不泄露凭据
- **WHEN** 上游错误正文包含密钥、令牌或超长响应内容
- **THEN** 持久化冷却原因与日志 MUST 仅包含稳定故障族、状态码、受限脱敏摘要和截止时间
- **AND** 系统 MUST NOT 保存完整敏感正文
